# 养车本 · 产品定义 v0.3

个人用车工具（indie）。手机上的养车账本 + 提醒：记录保养/维修/费用，按里程或时间提醒，卖车可导出履历。不控车。

工作名：**养车本**。与 Jelly Rabbit 品牌无关。

---

## 1. 定位与非目标

**定位**  
跨品牌的个人养车履历本：记下来、提得醒、卖车能证明。数据以本地为主，不绑车厂。

**非目标**  
- 车机、远程控车、OTA、CAN、深度车载软件  
- 强依赖官方控车 API / OBD（首期不接硬件）  
- 4S / 车队 SaaS、社交社区、电商导流养车服务  
- 「大而全车辆管家」功能堆叠

## 3. 目标用户与核心场景

**首要用户**  
自己养车的个人车主；有保养焦虑、票据易丢、卖车时说不清履历。电车是重要子集，不是唯一。

**核心场景**  
1. 保养后：拍照或手填 → 记下项目、里程、花费 → 设下次提醒  
2. 日常：临近保养/保险/年检时被提醒  
3. 卖车前：导出履历 PDF  
4. （二期）充电成本账本  

---

## 4. v0.3 硬约束（Architect 评审后写入）

### A. OCR：草稿，不是自动记账

- **话术：**「拍张收据，识别成草稿；你确认后才保存。」禁止「自动记账」承诺。  
- **流程：** 拍照 → 确认页（全部可改）→ 入库；失败保留照片并手填。  
- **技术默认：** 端侧 Vision 出草稿；云端可选、默认关。  
- **验收：** 多数机打收据上，确认页能预填 **日期、金额、至少一个项目**；不验收字段全对或手写模糊稳准。  

### B. 里程提醒：依赖用户更新

- 时间到期：系统本地通知。  
- 里程到期：无系统事件；仅在用户改里程 / 打开 App / 记一笔时重算。  
- **首页「下一件待办」是真相源**（推送可能被关）。  
- MVP：首页与记一笔可快速改里程；临近时可软提醒「该更新里程了吗？」；「先到者」估算须标注仅供参考。  
- 推送权限：用户 **创建第一条提醒时** 再请求。  

### C. 备份包 ≠ 履历 PDF

| | 履历 PDF | 备份包 |
|---|---|---|
| 对象 | 买家 / 阅读 | 自己迁移换机 |
| 内容 | 干净时间线 + 合计 | JSON/ZIP + 收据图 |
| MVP | ✅ | ✅ |
| Pro | 去水印 / 更好排版 | 备份不绑付费 |

## 5. MVP 范围

**做**  
1. 一辆车档案（手填车型、当前里程、动力类型 fuel/bev/hev/phev）  
2. 记保养/维修：手填或 OCR 确认后入库；收据图存档  
3. 提醒：里程 / 时间 / 先到者 + 本地通知（遵守 §4B）  
4. 首页：下一件待办 + 最近时间线；主按钮「记一笔」；车辆/导出在「…」  
5. 履历 PDF（干净列表）  
6. 备份包导出 / 简易恢复  
7. 买断 Pro（如去水印 PDF）；恢复购买  

**不做**  
完整充电账本、多车入口（勿露残缺）、云账号、默认开云端 OCR、车厂 API/OBD。  

界面与流程细节见 `SCREENS.md`。

---

## 6. 商业化

- 免费：1 辆车、记录、提醒、OCR（可合理限次）、基础 PDF（可轻水印）、**备份包**  
- Pro 买断：更高/无限 OCR、去水印更好 PDF、多车（二期）  
- 价格访谈测：¥28 / ¥48 / ¥68  

---

## 7. 技术假设（立项）

- SwiftUI + SwiftData 或 GRDB；图片 FileManager，库内仅路径  
- PDFKit；StoreKit 2  
- OCR 默认 Vision  
- 粗估 **6–10 人周**  
- 风险：中文 OCR 预期、里程不更新、IAP 边界  

数据模型草图见 Architect 意见（Vehicle / Record / ReminderRule / AppSettings）；`type=charging` 与 `powertrain` 预留即可。

---

## 8. 验证计划

- **2 周：** 约 10 车主访谈（含电车）— 履历/提醒/付费；顺带问充电痛点  
- **3–4 周：** TestFlight — 手填 + OCR 确认 + 提醒 + PDF + 备份  

成功信号：真实录入、打开过提醒、有人要导出或愿付费；OCR 确认页改动率可接受。
